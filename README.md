# Pawside Pet Services

Marketing site, booking flow, and customer dashboard for Pawside Pet Services — built with Next.js (App Router), TypeScript, Tailwind CSS, and Framer Motion.

## Getting started

```bash
npm install
npm run dev      # http://localhost:3000
npm run build    # production build
npm run start    # serve the production build
npm run lint     # next lint
npm run typecheck
```

Node 18.18+ is required (Next.js 15).

### Environment

| Variable | Required | Purpose |
| --- | --- | --- |
| `NEXT_PUBLIC_SITE_URL` | Production | Canonical URLs, sitemap, structured data. Defaults to `https://pawside.co`. |

Payment, email, and persistence keys are documented inline where they'll be needed — see `lib/api.ts` and `app/api/*/route.ts`.

## Brand

Both brand anchors were sampled directly from the official logo artwork with `scripts/sample-logo.mjs`:

| Token | Hex | Role |
| --- | --- | --- |
| `navy.900` | `#011C35` | Brand ink — headlines, primary buttons, dark surfaces |
| `mint.500` | `#36CEC1` | Accent only — hairlines, eyebrows, small emphasis |

Full 50–950 ramps for `navy`, `mint`, and the warm-neutral `sand` gray were generated by `scripts/build-ramps.mjs` and live in `tailwind.config.ts`. Semantic aliases (`--brand-navy`, `--surface`, `--ink`, `--accent`) are in `app/globals.css`.

Typography is **Poppins** for display and the logo wordmark (it matches the wordmark's geometric, single-story `a` and rounded terminals), **Inter** for body and dense UI. Both load through `next/font/google` and are exposed as `--font-display` / `--font-sans`.

Logo assets live in `public/brand/` (background-free light and on-dark variants). Use the `<Logo />` component rather than the raw files:

```tsx
<Logo variant="full" | "horizontal" | "mark" | "wordmark" theme="light" | "dark" />
```

`scripts/process-logo.mjs` regenerates the transparent assets and app icons from the source export.

## Structure

```
app/                 Routes (App Router)
  api/               Mock booking, checkout, and contact endpoints
  account/           Signed-in dashboard (noindex; mock session)
  book/              Multi-step booking flow + confirmation
  services/[slug]/   Per-service SEO pages
  locations/[slug]/  Local landing pages
  policies/[slug]/   Cancellation, safety, privacy, terms
components/
  booking/           Booking flow steps and order summary
  brand/             Logo
  dashboard/         Account shell, visit cards, report cards
  layout/            Navbar, Footer, mobile sticky CTA
  sections/          Composable page sections
  ui/                Primitives — Button, Card, Field, Photo, Section…
data/                All editable content and pricing
lib/                 Quote engine, SEO helpers, booking logic, API client
scripts/             One-off brand asset tooling
types/               Shared domain types
```

## Editing content

Nothing in `components/` needs to change to update the business. Everything below is a data edit:

| File | Controls |
| --- | --- |
| `data/site.ts` | Phone, email, hours, service radius, trust points, policy windows |
| `data/services.ts` | The six services, their copy, durations, and SEO metadata |
| `data/pricing.ts` | Base rates, additional-pet fees, surcharges, recurring discounts, holidays |
| `data/addOns.ts` | Add-on catalog and suggested pairings |
| `data/memberships.ts` | Tiers, bundles, gift cards, referral program |
| `data/serviceAreas.ts` | Towns and neighborhoods — each generates a local landing page |
| `data/faqs.ts`, `data/testimonials.ts`, `data/team.ts`, `data/policies.ts` | Supporting content |
| `data/media.ts` | Every image slot, with a photography brief per slot |

Prices are stored in **cents** throughout. `lib/pricing.ts` is the only place quotes are calculated — the homepage estimator, the booking flow, and the server-side re-price in `app/api/booking/route.ts` all call the same `buildQuote()`.

## Photography

`data/media.ts` ships with `src: null` for every slot, so `<Photo />` renders an on-brand gradient placeholder with the logo's heart motif. Drop in a real image by setting `src` — no component changes, and the alt text and dimensions are already written. Remote hosts must be allowed in `next.config.ts`.

## Backend integration

The site is fully functional as a front end with mocked persistence. The seams are marked:

- `lib/api.ts` — client for booking, contact, and checkout intents
- `app/api/booking/route.ts` — validates and re-prices server-side; add persistence and notifications here
- `app/api/checkout/route.ts` — returns a placeholder PaymentIntent; swap in Stripe
- `app/api/contact/route.ts` — add your email provider or CRM
- `components/dashboard/AccountShell.tsx` — reads a mock customer; replace with a real session

## Accessibility and SEO

Semantic landmarks, visible focus rings, keyboard-navigable accordions and steppers, `prefers-reduced-motion` respected on every animation, and layouts verified down to 375px. Metadata is generated by `lib/seo.ts`, which also emits LocalBusiness, Service, FAQPage, BreadcrumbList, and WebSite JSON-LD. `app/sitemap.ts` and `app/robots.ts` cover every public route and exclude `/account`.
